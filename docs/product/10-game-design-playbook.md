# Tikerino Game Design Playbook (14 Sep 2026)

## Executive summary
A strong learning game must succeed as both a game and a learning system: intended player experience -> observable behavior -> mechanics and content -> measurable learning outcome. Tikerino already has a strong instructional loop (short lesson, worked example, point-in-time exercise, immediate feedback, XP, reveal). Next: mastery progression, failure recovery, assessment moments, accessibility, player research, social motivation. Retention should come from growing competence, not pressure.

## Ten operating principles
1. Start with the player experience, not a feature list (MDA backward).
2. Make learning the core play - the winning action exercises the target skill.
3. Protect autonomy, competence, relatedness.
4. Keep challenge at the edge of current skill; diagnose rather than punish failure.
5. Teach in context through action; progressive disclosure.
6. Fast, explanatory feedback - what happened, why, what to notice next.
7. Retrieval and spacing - varied recall, not near-identical repetition.
8. Progress marks growing capability; rewards never the main reason to act.
9. Access as a core constraint (text, captions, targets, non-colour cues, speed control, reduced motion).
10. Test behavior, not opinions.

## Key do's and don'ts
- One observable objective per lesson; every exercise requires the target skill; define success, misconception, feedback and transfer case before producing content.
- Player performs the core action in the first minute; no long intros or lore dumps.
- Worked example -> close problem -> varied transfer; repeated errors trigger intervention; low-stakes retries; summative "market exams" on unseen cases. Don't make hints cost scarce currency.
- Feedback points to exact chart evidence; celebrate mastery, reasoning, recovery and consistent practice; show skill progress, not only XP. Don't reward speed when judgment is the objective.
- Return reasons: unfinished mastery, fresh transfer cases, useful goals. No guilt, fake urgency or confusing currencies.
- Social: start learning-safe (friend groups, cooperative challenges, shareable explanations); no open chat first; no leaderboards rewarding volume.
- Economy/ethics: plain prices, easy cancel, separate payment from progression, state that exercises are educational and not financial advice, minimize data.
- Research: one decision and one risk per test; observe without coaching; test comprehension now and retention later; segment by prior knowledge, device, accessibility needs.

## Workflow
Frame -> Specify -> Prototype -> Internal check -> First-time-user test (5-8 players) -> Learning test -> Iterate -> Instrument -> Gate on both experience and learning evidence -> Post-launch review.

## Tikerino priorities
- P0 Validate before scaling content: cold-cohort first-session test and delayed learning check; skill-mastery model alongside XP; error taxonomy (which misconception each wrong answer represents).
- P1 Strengthen the learning game: first summative market exam on unseen charts; recovery after repeated failure (hint, worked example, easier parallel case, retry); spaced mixed review; feedback pointing to specific visual evidence.
- P2 Retention without pressure: streak protection/recovery path; meaningful return goals and optional reminders; small social-learning test before any leaderboard.
- P3 Accessibility and production discipline: audit every lesson for captions, text alternative, contrast, target size, motion, pacing, non-colour cues; per-lesson content design brief.

## Metrics that matter
Learning: first-attempt accuracy by skill; transfer accuracy; delayed retention; misconception rate; hint-to-success; mastery time. Experience: onboarding completion; time to first meaningful action; voluntary return; frustration exits. Fairness/access: gaps by device, prior knowledge, mode, accessibility setting. Guardrails: notification opt-out; streak-related churn; excessive sessions; complaints.
