# Claude Code kickoff prompt - Tikerino MVP, day-one build

Paste everything below the line into a fresh Claude Code session in an empty directory. It is self-contained; no other context is needed.

---

Build the first runnable MVP of **Tikerino**, a Duolingo-style investing-education game. One-liner: a mobile game that teaches you to read markets one tiny principle at a time, practiced on chart exercises with instant feedback. All charts are **synthetic, generated practice data** - there is no real market data, no real tickers, no dates, and nothing anywhere may look like investment advice.

## Locked scope (do not expand)

- Exactly 2 topics: trading fundamentals and candlestick reading. The full starter curriculum already exists as content - you build the code that plays it, not the content.
- Exercise types day one: `multiple_choice` and `pick_the_candle` only. No drag interactions.
- 6 screens: Onboarding (simple), Path home, Lesson card (principle card + guided example folded in), Exercise, Reveal/feedback, Profile/streak. Mobile-first, phone-sized. No exam mode, no accounts, no marketing pages.
- English only. One palette (Growth Green). Synthetic data only.

## Stack

- Vite + React + TypeScript, installable PWA (manifest + offline lesson shell), mobile-first.
- Framework-neutral TypeScript packages with no React imports, because the final client will be React Native and these port unchanged:
  - `packages/engine` - seeded deterministic OHLCV generator, scenario families, candle-rule resolution, accessibility narrative.
  - `packages/grading` - answer grading + XP scoring.
  - `packages/content` - content-pack types, loader, validation.
  - `packages/state` - progress, XP, streaks (localStorage day one).
- One thin **Fastify** (Node + TypeScript) server with exactly 2 endpoints, specified below. No database: content pack is a JSON file, audit records append to JSONL.
- Tailwind for styling.

## Specs you must implement against (provided as files)

The following files define the contracts. Ask the user to paste them or place them in the repo root; treat them as authoritative over this prompt if anything conflicts:

1. `tikerino-content-pack-v0.1.json` - the actual starter curriculum: 8 lessons, 15 exercises, all copy, charts referenced by seed. Load and render this; do not invent content.
2. `tikerino-content-schema-v1.md` - the schema the pack follows. Validate the pack at load; refuse to run on validation failure.
3. `tikerino-engine-grading-spec-v1.md` - the generator (exact PRNG + seed hashing), scenario families, window cutting, grading, XP scoring, endpoint request/response shapes, audit record shape, integrity tests.
4. `tikerino-design-tokens-v1.css` and `tikerino-tailwind.config.js` - the design tokens. Use them verbatim.

## The integrity contract (the product's core - do not weaken it)

- Every exercise chart is generated by the server from (scenarioFamily, seed, scenarioSpecVersion) using the exact seeded PRNG in the engine spec. Generation is deterministic: same seed -> same series, bit for bit, forever. Golden-seed replay tests prove it.
- The learner sees candles only through cut point T (the first `windowSize` candles). Post-T "reveal" candles are generated and held **only on the server**. The client bundle and the window endpoint must never contain or serialize post-T data. CI must include the negative test: scan every window payload for post-T candles.
- Grading happens server-side. `POST /api/answers` returns grading + XP breakdown + the reveal candles + the disclaimer in one response. The client shows the reveal only after this response; an offline answer locks locally and waits (deferred reveal).
- Charts are always labeled as generated practice data, and the reveal screen always shows the disclaimer from the content pack's `meta.revealDisclaimer`.

## Design + accessibility requirements (WCAG 2.1 AA, locked)

- Tokens: Growth Green `#10B981` brand; ink navy `#0F2B46`; coral `#FF6B57` and sunshine `#FFB020` accents (never inside the chart canvas); paper `#FAFAF7`. Full set in the tokens files.
- **Contrast rules are already worked out in the tokens file comments - follow them exactly.** The headline rule: text on green buttons is ink navy, never white (white on #10B981 fails AA).
- Candle colors are frozen data encoding, independent of brand: bullish `#0E9F6E`, bearish `#DC2626`, with mandatory non-color encoding: bullish = hollow body (paper fill, colored border), bearish = solid filled body. Color is never the only signal.
- Type: Baloo 2 for display, Nunito for body (Google Fonts, both OFL). Body base 18px; nothing under 16px anywhere; tabular numerals on charts.
- All touch targets >= 48x48px. Focus-visible 3px ring on every interactive element. Full keyboard operability: pick-the-candle must be playable by arrow keys + Enter, and via the screen-reader candle list, with identical grading.
- The chart exposes an ordered screen-reader alternative generated by `engine.describeCandles()`: one line per candle (direction, OHLC, body vs range, relative volume).
- `prefers-reduced-motion` disables the reveal animation.
- One idea per screen; the chart is the hero; short sentences; no jargon before it is taught.

## Definition of done for this session

`npm run dev` starts server + client, and on a phone-sized viewport I can play the full loop end to end: onboarding -> path home -> open a lesson -> read the principle card -> step through the guided example -> answer exercises on charts cut at T -> submit -> see grading, XP, the animated reveal of post-T candles, and the disclaimer -> return to the path with XP and streak updated. All 15 starter exercises playable. Replay test green (regenerating a golden seed set matches stored hashes). Negative test green (no post-T candles in any window payload). axe DevTools scan of the exercise and reveal screens shows zero critical/serious issues.
